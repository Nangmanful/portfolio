구현한 기술

  • 도서관 방 · 참여 상태 API — Spring Boot로 방 생성 · 코드 초대 · 정원 판정과 참여 현황 게시 · 조회 API를 구현하고 React Native 로비 · 방 화면과 연결. 동시 입장 경합은 비관적 잠금으로 막았고, 방 생성 → 초대 → 독서 상태 표시까지 실기기로 검증
  • WebSocket 실시간 전환 — 참여 현황을 30초 폴링으로 조회하던 구조를 STOMP over WebSocket 구독으로 교체. 수신은 WebSocket 전용, 쓰기는 REST, 폴링은 폴백으로 남겨 채널이 끊겨도 동작하게 설계. 방 채팅도 같은 채널로 구현하고 실소켓 통합 테스트로 경계를 고정
  • 운영 인프라 · 배포 — AWS 개발 · 운영 서버 구성, GitHub Actions OIDC 자동 배포, OTA 업데이트와 최소 버전 부팅 관문(강제 업데이트 = 서버 정책 + 앱 부팅 게이트)
  • 일일 지표 — 신규 가입 · DAU · 발화 · OCR · 방 참여를 매일 아침 집계해 Slack으로 전송하고 가입 즉시 알림. 심사용 계정 제외, 하루 경계는 KST 자정

해결한 문제

  • 90초 만료 판정 폐기 — 상태 게시가 90초 끊기면 "읽지 않음"으로 판정하던 설계였는데, iOS는 화면만 꺼도 게시가 멈춰 책을 읽느라 화면을 끈 사용자가 "읽지 않음"으로 표시됐다. 시간을 늘리는 건 근거 없는 숫자로 문제를 미루는 것이라 판단해 판정 자체를 폐기하고 사용자가 설정한 상태를 유지, 앱 재시작 시 1회 게시로 잔존 상태를 정리. 강제 종료 시 상태가 잠시 남는 대가는 문서화
  • WebSocket 메시지 레이스 — 내가 보낸 채팅의 WebSocket 사본이 REST 응답보다 먼저 도착해 화면에 중복되는 경합. 클라이언트 메시지 ID 장부를 두고 REST 응답을 정본으로 삼아 덮어쓰도록 해결
  • 운영 책 검색 전면 500 — 특정 JPA 쿼리 조합이 운영에서만 무조건 500. 화면 오류 문구로 계층을 좁히고, 두 사용자에게 같이 발생한 점을 근거로 공통 서버 문제로 범위를 좁힌 뒤 Testcontainers로 그 쿼리만 재현해 원인을 확인하고 당일 운영 반영. CI가 못 잡은 이유는 검색만 메모리 DB로 돌았기 때문
  • RDS 비밀번호 자동 회전 — 아무도 바꾸지 않았는데 DB 인증 실패. 커넥션 풀 고갈처럼 보였지만 아래 계층의 인증 오류였고, Secrets Manager 7일 자동 회전이 원인. 앱이 시크릿을 직접 읽는 JDBC 드라이버로 바꿔 낡은 비밀번호가 생길 자리를 구조에서 없앰

구현한 기술

  • 서버 3분리 설계 — Spring Boot(인증 · 사업장 CRUD · 게이트웨이) / FastAPI + LangGraph(TCFD 보고서 생성) / ModelOps(리스크 계산 엔진). 저지연 CRUD, 수 분 걸리는 LLM 호출, 연간 대량 배치는 스케일링과 배포 주기가 달라 서버를 나눴다
  • Spring Boot 서버 전담 — JWT 인증, 사업장 CRUD, 분석 작업 상태 전이 관리, FastAPI 연동과 결과 저장까지 구현

  • 계산과 해석의 분리 — 처음엔 FastAPI 워크플로 안에서 점수 · 손실률까지 계산했다. LLM이 수치를 대신 만들지 않도록 계산 노드를 ModelOps로 외부화하고 결과는 DB에서 읽는 구조로 수렴

구현한 기술

  • 전체 흐름 — Next.js 14 + Kakao Maps 프론트, FastAPI + SQLAlchemy Core 백엔드. 회원가입 없이 초대 링크로 그룹에 참여해 취향 4항목을 입력하면 코스 생성 · 편집 · 공유까지 이어지는 흐름을 단독 구현
  • 그룹 취향 조율 추천 — 구성원 취향 비율로 일정 슬롯을 배분해 다수 취향은 코스 중심으로, 소수 취향도 최소 1곳 반영. TourAPI의 운영시간 · 휴무일 · 좌표 · 권역을 추천 판단 근거로 사용
  • 배포 · 운영 — Vercel + Render + cron-job.org 구성, SQLite → PostgreSQL(Supabase) 전환, 운영 중 발견한 문제 수정

해결한 문제

  • 공공데이터의 불완전함 — 운영시간이나 휴무일이 비어 있는 장소가 많았다. 조용히 제외하는 대신 "정보 없음, 방문 전 확인"으로 표시하고, 고정 장소가 휴무로 못 들어가면 못 넣었다고 안내하며, 파싱 실패 시 원문을 그대로 노출해 사용자가 판단하게 했다
  • 지역 코드 두 체계 — TourAPI의 구 · 신 지역 코드가 섞여 조회가 누락됐다. 두 체계를 통합해 같은 지역을 한 번에 조회
  • 지도 잔상 — 코스를 다시 그릴 때 지도 객체를 매번 새로 만들어 잔상이 남았다. 지도 객체는 한 번만 생성하고 마커만 갱신하도록 수정

구현한 기술

  • Stable Diffusion 인페인팅 모델 변형 · fine-tuning — LaDI-VTON 논문의 방식을 따라 Stable Diffusion 인페인팅 모델을 변형했다. 추론만으로 VRAM 24GB를 거의 써 전체 재학습이 어려웠고, parse map · skeleton(포즈맵) · 워핑 의상을 입력 조건으로 추가하고 첫 합성곱 층 채널을 0으로 초기화해 확장한 뒤, VITON-HD로 사전학습 모델을 fine-tuning(300k iteration)
